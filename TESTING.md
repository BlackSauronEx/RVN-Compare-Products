# TESTING.md — журнал реализации и тест-план

Живой документ: заполняется по мере сборки плагина. Каждый блок = шаг
работы → что уже работает → как проверить на стенде → известные ограничения.
Полная приёмка — в ТЗ, §17 «Критерии готовности Этапа 1 (MVP)».

> ⚠️ Файлов `.pot`/`.po`/`.mo` пока нет (локализация по коду развешана, сборка
> переводов — отдельный шаг после стабилизации строк).

---

## Шаг 0 — Скелет и совместимость

**Сделано:**
- `rvn-compare.php` (bootstrap): константы, реестр, автозагрузка классов `RVN_Compare_*`.
- `class-rvn-compare-plugin.php`: singleton-ядро, textdomain.
- `class-rvn-compare-compatibility.php`: Woo-гард + `admin_notices`, декларация HPOS.

**Как тестить:**
1. Установи папку `rvn-compare/` в `wp-content/plugins/`.
2. **Выключи WooCommerce** → активируй плагин → в админке должен появиться
   красный нотис «…требует установленный и активированный WooCommerce», сайт не падает.
3. **Включи WooCommerce** → активируй → нотиса нет, меню «RVN» появилось.
4. Проверь `Настройки WooCommerce → Дополнительно → Функции`:
   RVN Compare отмечен как совместимый с HPOS.

**Ограничения:** нет (шаг завершён).

**Как тестить:**
1. Авторизованным добавь товар кнопкой `[rvn-compare-button]` → счётчик
   `[rvn-compare-counter]` должен стать «1» без перезагрузки.
2. Открой **две вкладки** (магазин и страница сравнения): очисти список на одной,

4. Вкладка «Основное»: поменяй лимит/акцент → Сохранить → значения останутся.
5. Выставь галочки во «Таблице сравнения», сохрани «Основное» → галочки
   НЕ должны сброситься (фикс tab-aware).

**Ограничения:** лимит 12/«Прочее»/группы категорий ещё не применены
(нет Context/Categories); REST `GET /table` возвращает заглушку.

## Шаг 2 — Активатор + страница сравнения

**Сделано:**
- `class-rvn-compare-activator.php`: при активации — дефолты + страница.
- `class-rvn-compare-page-manager.php`: `create_page` / `ensure_page` (без дублей,
  восстановление из корзины) / `reset_page_content` / метка «Страница сравнения»
  в списке страниц / авто-вставка таблицы в конец (опция «Авто-вставка»).
- В админке («Основное»): селект страницы, кнопки «Создать страницу» /
  «Сбросить страницу», ссылка «Посмотреть страницу», уведомления после действий.

**Как тестить:**
1. **Удали плагин** (полностью, с файлами) → **установи заново**.
2. После активации должна появиться страница «Сравнение товаров» со слагом
   `rvn-compare`; в «Страницах» рядом с ней — метка «Страница сравнения».
3. Проверь, что в настройке «Страница сравнения» подставлена эта страница.
4. Открой страницу: должна показываться таблица (каркас/пустое состояние).
5. Удали страницу в корзину → в админке «Создать страницу» → восстановит/назначит.
6. «Сбросить страницу» → в содержимом останется только `[rvn-compare-table]`.
7. Убедись: повторная активация НЕ создаёт дубликат страницы.

**Ограничения:** авто-вставка добавляет шорткод только при включённой опции;
текст названия страницы берётся по локели (`determine_locale()`).

**Как тестить:**

5. Позиция «Отключить» → кнопка исчезла с витрины/страницы.
6. Товар-вариация в списке → добавляется родительский товар (normalization).

## Шаг 4 — Исключения товаров (админка)

**Сделано:**
- `excluded_products` — структурированный: `id => ['archive'=>0/1,'single'=>0/1]`.
- `buttons.php`: контекстная проверка `is_excluded($id,'archive'|'single')`.
- UI «Основное → Исключения товаров»: ввод ID (можно несколько через запятую),
  две галочки контекстов, список с флагами и ✕ удалением, уведомления.

**Как тестить:**
1. Введи ID товара → «Добавить в исключения» → товар в списке.
2. Открой витрину/карточку этого товара → кнопка сравнения исчезла
   (только по отмеченным контекстам).
3. Сними обе галочки → сохрани → товар удалён из исключений.
4. Несколько ID через запятую → добавились все.
5. Пустой/невалидный ID → сообщение об ошибке, без падения.

**Ограничения:** автопоиск товара по названию (`wc-product-search`) пока НЕ подключён —
только ручной ввод ID. (в бэклоге.)

**Как тестить:**

3. «Только различия» — остаются только расходящиеся строки.
4. Сворачивание/разворачивание групп стрелкой у заголовка.
5. Проверь значения полей (цена/артикул/рейтинг/наличие/вес/размеры) в строках.
6. Шорткод `[rvn-compare-table group="catN"]` — таблица только одной вкладки.

**Ограничения:**
- Слайдер (горизонтальная прокрутка на шаг/стрелки) и плавающая панель ещё НЕ реализованы.
- Серверный only-diff/скрытие пустых строк — включено; клиентский фильтр — есть.
- Вкладка «Таблица сравнения» в админке пока не редактирует группы/поля (UI следующий шаг);
  значения берутся из дефолтов.

## Шаг 6 — Слайдер и плавающая панель

**Сделано:**
- Слайдер: общий scroll-контейнер (шапка + ряды), фиксированная ширина колонки
  «контейнер / N видимых» (R2-02), шаг = 1 колонка, стрелки по краям,
  block/disabling стрелок по краям, синхронизация ширины через ResizeObserver.
- Плавающая панель: компактный клон шапки, появляется при уходе шапки за
  верх экрана, синхронизация прокрутки с основным слайдером, отступ настраивается.
- Sticky-подписи характеристик слева (не уезжают при прокрутке).
- Добавлены настройки: отступ плавающей панели (свои единицы), object-fit фото
  (contain/cover). Вкладка «Основное» разбита на понятные секции.

**Как тестить:**
1. Набери больше товаров, чем видимо на десктопе (напр. 7) → появились стрелки.
2. Клик по стрелке прокручивает ровно на ОДИН товар; на краю стрелка disabled.
3. Ширина колонок = контейнер / 5 (десктоп) и не «расползается» при 2–3 товарах.
4. Подписи характеристик остаются слева при прокрутке (sticky).
5. Прокрути страницу вниз — при уходе шапки появилась плавающая панель сверху;
   её колонки совпадают по горизонтали с основной таблицей.
6. Установи отступ панели 80px → панель видна ниже липкой шапки.
7. На телефоне/планшете число видимых 2/3 работает, touch-свайп прокручивает.

**Ограничения:**
- Плавающая панель — компактная (фото/название/цена/✕, без нижней кнопки «Купить»).
- Touch-свайп использует нативный scroll (без snap на чёткий шаг) — допустимо.
- Синхронизация панели идёт через transform по scrollLeft (стенд-тест обязателен).

- `admin.php` вкладка «Таблица сравнения»:

  - таблица ACF/Custom Meta (meta key / название / группа / тип / вкл, + пустая строка для нового);

**Как тестить:**
1. Переименуй группу «Основное» → сохрани → в шапке таблицы название изменилось.
2. Добавь ACF-meta поле (любой существующий meta key) → в таблице появилась строка.
3. Создай группу категорий (2 категории) → во вкладках таблицы эти категории объединились.
4. Категории, вошедшие в группу, недоступны (disabled) при создании следующей группы.
5. Выключи «Полное описание» через meta? (поле из core-строки — пока отдельным UI нет;
   галочки поведения: подсветка/пустые строки/«Только различия» — проверить на фронте).

**Ограничения:**
- Переключение «вкл/выкл» для core-полей Цена/Артикул/… ещё не выведено в UI
  (значения по умолчанию из `fields.php`); добавлю в следующем шаге вместе с drag&drop.
- Drag&drop групп/полей и авто-нейм категорийных групп пока не подключены.
- Группы категорий: удаление/редактирование существующих — не выведено (только просмотр и создание).

## Шаг 8 — «Дизайн таблицы» (вкладка админки)

**Сделано:**
- Вкладка «Дизайн таблицы» из 4 секций: Цвета / Типографика / Геометрия /
  Кнопка «Купить» + справа sticky-превью демо-таблицы из 2 фейковых товаров.
- Живой превью: при вводе admin.js мгновенно пересчитывает CSS-переменные

- Сохранение: плоские ключи `design[секция][поле]` (сохранение вкладки не трогает
  другие), цвета санитизируются через `sanitize_hex_color`, числа absint,
  режимы buy — whitelist buy/shortcode/hidden. Поле «мой шорткод» (buy_shortcode).
- Фронт: `design_css()` печатает inline-CSS `style#rvn-compare-design-css` с
  переменными в область `.rvn-compare-table, .rvn-compare-floating` + object-fit;
  frontend.css дополнил `:root` дефолтами новых переменных.
- Кнопка «Купить»: выбор настройки buy_header/buy_bottom/buy_floating;
  сервер рендерит 3 слота (`data-buy-slot`), JS переносит компактную кнопку
  в плавающую панель; если в панели hidden — показывает фото.

**Как тестить:**
1. Поменяй «Акцент» → превью тотчас окрасится; сохрани → на странице
   сравнения цвет активной вкладки/бейджа/кнопок «Купить» изменился.
2. «Подсветка различий» #  → в превью ячейки с отличающимися значениями сменили цвет.
3. «Высота фото» 60 → фото в превью уменьшились; на фронте тоже.
4. Кнопка «Купить» в плавающей панели = «Скрыть» → при прокрутке таблицы
   в компактной панели вместо кнопки видно фото.
5. Нажми Esc в любом поле дизайна → вернётся сохранённое значение; в
   color-picker значения валидируются (невалидный hex не применяется).

**Ограничения:**
- Полные режимы кнопок/тостов конструктора элементов (§6.4) — в следующем шаге
  (RD-02); тексты тостов пока на вкладке «Дизайн элементов и кнопок».
- «Наследовать стили темы» и выбор отдельного шорткода на кнопку (несколько) —
  сделано поле-одиночка `buy_shortcode`; в UI он пока не выведен (добавим в RD-02
  вместе со шорткод-конструктором кнопок «Купить»).
- Насыщенность значений использует отдельную переменную `--rvn-compare-value-weight`
  (чтобы не конфликтовать с насыщенностью кнопок `--rvn-compare-weight`).

## Шаг 9 — «Дизайн элементов и кнопок» (RD-02)

**Сделано:**
- Новый класс `class-rvn-compare-design.php`: SVG-санитайзер (DOMDocument,
  whitelist svg/g/rect/line/polyline/polygon/path/circle/ellipse + атрибуты;
  короткий эмодзи тоже пропускается), дефолты кнопок/тостов (§11), слитие
  сохранённого с дефолтами, генераторы `elements_css()`, `button_inner_html()`,
  `counter_inner_html()`, `elements_data()`.
- Вкладка «Дизайн элементов и кнопок»: тексты (8 полей), 3 блока кнопок (режим,
  SVG/эмодзи, бейдж у счётчика, свой класс, стили normal+hover), 4 блока тостов
  (позиция десктоп/моб, значок + позиция значка, прогресс-бар, 4 цвета) +
  превью на полосатой подложке с ручной кнопкой «Обновить предпросмотр».
- Сохранение: плоские ключи `es[<раздел>][<поле>]`, ветка санитизации
  `sanitize_element()`; тексты кнопок/тостов — на этой вкладке (другие не сбрасываются).
- Фронт: кнопки рендерятся с иконкой/режимом (авто + шорткоды); тосты получили
  `data-kind`/позиции десктоп-мобайл/иконку/прогресс-бар, `toast()` теперь
  принимает тип. Иконки/режим «bare»/бейдж — стилизованы в CSS.

**Как тестить:**
1. Переключи режим кнопки «Сравнить» → «Только текст» → сохрани → на витрине
   кнопка без иконки, только текст.
2. Вставь SVG в «Иконка» → сохрани → иконка появилась; вставь `<script>` —
   санитайзер его вырезал (проверь во вкладке после сохранения).
3. Позиция бейджа счётчика «Сверху (угол)» → в меню бейдж в углу.
4. Тост «добавлен»: позиция десктоп «Верх справа», мобайл «Низ центр» →
   на широком экране тост сверху справа, на мобильном снизу; прогресс-бар
   сужается до скрытия.
5. Пустой текст у тоста «удалён» + пустой значок → тост не показывается (R4-04).

**Ограничения:**
- Позиции тостов десктоп/мобайл: для центрирования верхних/нижних позиций
  используется translate(-50%…), на мобильных left/right перекрывает — точную
  геометрию стоит вычитать на реальном авторе; при желании подгоню.
- «Наследовать стили темы» (чекбокс §6.3) и множественные шорткоды кнопок
  «Купить» (массив) — осталось; сейчас buy_shortcode — одиночка.
- Превью элементов перерисовывается кнопкой/при загрузке; автоперерисовка каждой
  вкладки SSR не привязана к input (цвета/формы — при сохранении).

## Шаг 10 — доработка «Таблицы сравнения»

**Сделано:**
- `core_fields` в настройках: включение/выключение, переименование, подсказка [?],
  группа и порядок (drag&drop в админке; reflects в `core_fields_customized()`).
- Группы характеристик: переименование, добавление (новый slug), удаление
  (поля уходят в «Характеристики»), перетаскивание за ручку ⠿.
- Группы категорий: переименование, удаление (маркер category_groups_delete)
  + список категорий; занятые — disabled.
- Фронт: тултипы [?] полей (CSS `attr()`), «Только различия» сохраняется в
  localStorage, сворачивание групп — в localStorage (по ключу группы);
  переключатель «Только различия» скрывается при
  show_only_differences_toggle=выкл; группы умеют быть статичным заголовком
  (collapse_groups=выкл) и «свёрнутыми по умолчанию» (groups_default_state).
- «Полное описание» больше не вставляется принудительно последним — порядок
  теперь 100% управляется drag&drop (в дефолте оно и так последнее).

**Как тестить:**
1. Выключи «Цена» (core-поля) → в таблице строка пропала; включи обратно.
2. Переименуй «Артикул» в «SKU» + добавь подсказку → в таблице новое имя и [?],
   при наведении — подсказка.
3. Перетащи «Вес» вверх за ручку → после сохранения порядок строк изменился.
4. Добавь группу «Экран» → в таблице появился новый разделитель; удали её →
   поля вернулись в «Характеристики».
5. Удали группу категорий → её категории снова доступны для новой группы;
   вкладки таблицы больше её не включают.
6. Включи «Только различия», обнови страницу → тумблер остался включённым
   (localStorage); сверни группу и обнови — тоже осталось.
7. groups_default_state=«Свёрнуты» → группы открываются свёрнутыми;
   collapse_groups=выкл → заголовки без стрелки.

**Ограничения:**
- Drag&drop — ванильный HTML5 (ручка). «Вкл/выкл все» и поиск/фильтр по полям
  (§6.2 п.2) ещё не сделаны.
- Автоподстановка названия группы категорий при 1 выбранной и иерархический
  чекбокс-список с поиском (§6.2 п.3) — упрощённый mselect (как в Шаге 7).
- Тултипы — чистый CSS (`title`-атрибут не используется); длинные подсказки
  могут вылетать за экран на узких колонках.

**Как тестить:**
1. Режим «Показывать ТОЛЬКО на выбранных» + страница «Главная» → на карточках
   остальных страниц кнопка исчезла.
2. URL-шаблон `promos/*` в режиме «Скрывать» → на /promos/… кнопка скрыта.
3. Исключения: начни вводить название в поиск → выпали товары; добавь пару
   (multiple) → в списке исключений появились.
4. Исключи категорию «Ноутбуки» → все товары категории потеряли кнопку.
5. «Очистить список» → товарные и категорийные исключения пусты.
6. Убедись, что страница сравнения отдаёт `meta robots noindex,nofollow`.
7. uninstall: отметь «Удалить настройки», удали плагин → опция стёрта

**Ограничения:**
- Быстрые пресеты (§6.1 п.2 «архивы/товары/главная») реализованы через
  режимы + страницы + URL, без отдельных кнопок-пресетов.
- AJAX-поиск использует стандартный endpoint WC и класс `.wc-product-search`
  (нужен active WooCommerce + его ассеты); без WC секция выводится пустым select.
- URL-сравнение — по path (`$wp->request`); query-строка игнорируется.

## Шаг 14 — кнопка «Добавить товар» (R3-01)

**Сделано:**
- Чекбокс «Кнопка “Добавить товар”» (вкл по умолчанию) на вкладке «Основное»
  → `add_product_button`; настройка окрывает кнопку в тулбаре и в пустом состоянии.
- REST `GET /search?q=…`: `wc_get_products` (publish, `s`, до 15 → отсев до 10),
  публичные и не-исключённые товары, вариации пропускаются (R2-16); rate limit
  (для гостей тоже); ответ: id/title/sku/price/inList/limit.
- Модал «Добавить товар»: debounce-поиск 300 мс, список подсказок с ценой/SKU,
  кнопка «Добавить» (disabled «В списке»), закрытие по ✕/клику подложки/Escape.
- Добавление через общий `toggle` (росты/лимиты как у кнопок); переход
  «пусто → есть товары» делает reload (сервер отдаёт таблицу).
- Шорткод `[rvn-compare-add-button text="…"]` (кнопка открытия модала где угодно).

**Как тестить:**
1. Вкл/выкл чекбокс «Кнопка “Добавить товар”» → кнопка появляется/исчезает
   в тулбаре и в пустом состоянии (с пустым списком).
2. Открой модал, набери часть названия/SKU → подсказки ≤10, вариации не видны,
   исключённые в админке (товары/категории) не появляются.
3. Нажми «Добавить» → строка становится «В списке», тост «добавлено», таблица
   перерисовывается (вкладки/счётчик обновились); глобальный/групповой лимит
   блокирует с тостом «максимум».
4. Закрытие: ✕, клик мимо окна, Escape; повторное открытие сбрасывает запрос.
5. Шорткод `[rvn-compare-add-button]` на произвольной странице открывает модал.
6. Гость: поиск работает (rate limit), добавление в localStorage.

**Ограничения:**
- Переход «пусто → есть товары» требует перезагрузки страницы (серверный рендер),
  т.к. пустого viewport с тулбаром нет.
- Поиск — по названию/содержимому через штатный `s` WooCommerce (SKU не везде
  индексируется); полнотекст зависит от WC.
- Модал всегда доступен для добавления; правая «Купить»/исключения не проверяют
  роль пользователя (та же модель, что и toggle).
- После добавления из модала строки перерисовываются (состояние «В списке»).
